**Convention**: 🖼️ = full screen, 📋 = modal / bottom sheet, ⚙️ = settings-style sub-screen.

## H. Global UI elements (app chrome)

These appear on every screen, not as standalone screens — but worth designing as components in Figma:

- **Top bar** — current section title + 🔔 bell (nudge inbox count) + ⚙️ gear
- **Bottom tab bar (mobile) / sidebar (desktop)** — the 5 tabs (Home / Accounts / Activity / Plans / Reports)
- **Add transaction FAB** — bottom-right floating button on Home, Accounts, Activity
- **Toast / snackbar** — for transient confirmations (transaction added, suggestion accepted)
- **Empty states** — every list view needs one (no accounts yet, no budgets, no transactions on this account)

## I. Component library to build first in Figma

Working back from the design tokens in the project, these are the components that show up most:

1. **Card** — white background, haze-teal border, 12px radius. Used everywhere on the dashboard.
2. **Card-dark** — deep-ink background. For featured / hero summary cards.
3. **Tag** — pill shape. Income (seafoam tint), default (ice-wash tint). Used on transactions.
4. **Progress bar** — 5px tall, pill shape. Variants: default (ocean-teal), warning (amber), danger (coral), success (seafoam). Used on budgets.
5. **Account row** — icon + name + type tag + balance. Used in lists everywhere.
6. **Transaction row** — icon + description + category tag + amount (mono font). The single most-used row.
7. **Icon container** — 36px circle, ice-wash background. Holds the leading icon on rows.
8. **Buttons** — primary (ocean-teal fill), secondary (ice-wash fill), outline, success, danger, ghost. Per the tokens.
9. **Nudge card** — title + body + severity dot + dismiss. Used in inbox and on dashboard.
10. **Empty state** — illustration placeholder + headline + body + CTA.

## J. Order to design in

If you want a fast first pass before designing everything:

1. **Component library** (the 10 above) — pays for itself immediately.
2. **Dashboard** — the screen you'll see most. Forces the cards into existence.
3. **Accounts list + detail** — the second-most-visited area.
4. **Ledger + add transaction** — the data-entry path.
5. **One report detail (Cash flow forecast)** — pressure-tests how a complex chart card looks.
6. **Settings hub + one sub-screen** — proves the navigation pattern.
7. **First-run setup** — easy to defer; until then, mock with seeded data.
8. **Everything else** — fills in once the patterns above are settled.

A vertical slice (1 → 4) is enough to start coding against. The rest can be designed in parallel with build.
